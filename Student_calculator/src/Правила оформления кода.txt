1. Имена должны быть понятными.

Классы - существительные, оформляются в стиле CamelCase (каждое новое слово с большой буквы).
Методы - глаголы, оформляются в стиле сamelCase (первое слово (глагол) с маленькой буквы)
Переменные - названия, должны отвечать на вопрос "что это?" и быть понятными в обозначении.

Хорошо

public class CatClass
String name = Паштет;
public String getName

Плохо

public class сatClass // нарушен стиль CamelCase, класс назвали как метод
String n = Паштет;    // непонятное название переменной
public String GetName // нарушен стиль сamelCase, метод назвали как класс

2. КОНСТАНТЫ_НЕЛЬЗЯ_МЕНЯТЬ.

Константы (final) пишутся в верхнем регистре, слова разделяются подчеркиванием.

Хорошо

public static final double PI = 3.14;

Плохо

public static final double pi = 3.14;

3. Код должен читаться.

Каждый новый блок сдвигается на 4 пробела, открывающая фигурная скобка в той же строке, что и объявление,
закрывающая-на новой, под началом блока. Это стандарт 1TBS (Единствнно Правильный Стиль Расстановки Скобок),
экономит место и упрощает чтение.

Хорошо

public static void main(String[] args) {
String name = "Ирина";
}

Плохо

public static void main(String[] args)
{
String name = "Ирина";
}

4. Код должен использоваться.

Если переменная объявлена, но нигде не используется — она мусор. IDEA сразу обозначает такие места.
Всё, что не используется, — удалять.

Хорошо

public double calc(double x) {
    return x * 2;
}

Плохо

public double calc(double x) {
    double y = x * 2; // y нигде не используется
    return x * 2;
}

5. Пробелы после операторов.

Все символы отделяются пробелами, иначе код нельзя будет прочитать. Между ключевым словом (if, for, while)
и открывающей скобкой всегда ставится пробел, а между вызовом метода и его скобками — нет.

Хорошо

if (x > 5 && y < 10) {
    System.out.println(x + y);
}

Плохо

if(x>5&&y<10) {
System.out.println(x+y);
}
